# word_guess

Некоммерческая русскоязычная игра по механике «5 букв». Разрабатывается по этапам; установка как PWA запланирована.

## Текущее состояние

Версия **0.4.0**: доступны регистрация без подтверждения, вход/выход, партии на 4/5/6 букв, шесть попыток, сдача и немедленная следующая игра. Строки сохраняются на сервере; обновление страницы и переключение длины восстанавливают партию. Есть физическая и экранная клавиатуры, раскрытие клеток, доступные обозначения статусов и толкование в итогах. Работают очки и монеты за победу, магазин, инвентарь и три подсказки. Системная, светлая и тёмная темы сохраняются отдельно для каждого пользователя и применяются до запуска React. Кампания, сундуки, рейтинг и PWA ещё не реализованы. Требования находятся в [plan.md](plan.md).

После входа нажмите «Играть», выберите длину и начните партию. Незавершённая игра одна на пользователя и длину; после победы, проигрыша или сдачи можно сразу открыть следующее слово. Принятые строки и итог восстанавливаются после перезагрузки, неотправленные буквы — нет. Неизвестное слово, неверная длина и повтор не тратят попытку; Ё принимается как Е. Ответ и толкование сервер раскрывает только после завершения. При потере ответа «Повторить действие» отправляет тот же ключ операции; при конфликте вкладок обновляется серверное состояние.

Регистрация даёт **150 монет и одну случайную букву**. Магазин открывается по балансу в шапке: случайная буква — 60, выбранная позиция — 100, три лишние буквы — 25 монет. Покупка добавляет один предмет; применение подтверждается отдельно на экране партии. Можно отменить выбор позиции. На партию разрешены два открытия буквы и одно удаление лишних; последняя неизвестная позиция не раскрывается. Открытые буквы можно подставить в строку, они не мешают проверять другие слова.

Очки и монеты рассчитывает сервер по правилам плана. Подсказки уменьшают очки, но не монеты за победу; проигрыш/сдача дают ноль и не возвращают предметы. Итог сохраняет награду и число использованных подсказок. При потере ответа покупку или применение можно повторить тем же ключом без дополнительного расхода. Цены, цели, остатки, ограничения и прогноз очков приходят с сервера.

Логин: 3–32 русские или латинские буквы, цифры или `_`, регистр не важен. Имя: 1–40 символов, пароль: 8–128 символов. Почта не требуется; восстановление пароля пока отсутствует. Пароли хешируются Argon2id. Сессии хранятся в SQLite в виде хешей случайных токенов, cookie имеет HttpOnly/SameSite и срок 30 дней по умолчанию. Выход отзывает сессию текущего браузера; другие устройства остаются авторизованными. В localStorage хранится только выбор темы. Аккаунт сверяется с сервером при загрузке, возвращении в окно и уведомлении из другой вкладки.

Чистая и повторная установка Windows проверены в каталоге с пробелами, включая оба bat-сценария, остановку серверов и сохранность БД. Dockerfile и Compose подготовлены, но полный запуск контейнера **не проверен**: Docker в рабочей среде отсутствует. Завершение проверки этапа 1 требует доступного Docker.

## Запуск в Windows

Нужны **Python 3.12+**, **Node.js LTS 22.12+ или 24+** и npm в PATH. Проверено на Python 3.13.9 / Node.js 24.18.0 / npm 11.16.0. Глобальное ПО сценарии не устанавливают. Первый запуск требует интернета.

Из PowerShell в корне проекта:

```powershell
.\run.bat
```

Открыть `http://127.0.0.1:8000`. Один Uvicorn обслуживает API и собранный frontend. Остановка — Ctrl+C; при стандартном запросе Windows о завершении batch-файла подтвердить остановку.

Разработка с перезагрузкой Python и Vite:

```powershell
.\run-dev.bat
```

Открыть `http://127.0.0.1:5173`; `/api` проксируется в FastAPI на порт 8000. Сценарий управляет обоими серверами; Ctrl+C останавливает их. Браузер автоматически не открывается.

Сценарии работают из своего каталога, создают `.venv`, устанавливают зависимости по lock-файлам, проверяют контент, применяют миграции и seed. Повторный запуск пропускает неизменившиеся зависимости и production-сборку; БД не удаляется. Отпечатки и кэш находятся в `.cache`. Подготовка без запуска сервера:

```powershell
.\run.bat --prepare-only
```

## Docker Compose

Подготовленная команда, ожидающая проверки на машине с Docker:

```powershell
docker compose up --build
```

По конфигурации сервис доступен на `http://127.0.0.1:8000`. Сборка многоэтапная: Node собирает frontend, Python устанавливает серверные зависимости с проверкой хешей. Перед API выполняются проверка контента, миграции и seed. Healthcheck обращается к `/api/health`.

SQLite находится в `/data/word_guess.db`, каталог `/data` подключён к постоянному named volume `word_guess_data`. Обычный `docker compose down` и пересборка сохраняют volume. Удаление volume для обслуживания не требуется. Исполнение этих команд в текущей среде не проверялось.

## Конфигурация и данные

Можно скопировать `.env.example` в `.env` и изменить настройки; без этого используются значения по умолчанию. Переменные окружения имеют приоритет над `.env`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite:///data/runtime/word_guess.db` | Только файловая SQLite; относительный путь считается от корня проекта |
| `SQLITE_BUSY_TIMEOUT` | `5000` | Ожидание блокировки в миллисекундах, 1–60000 |
| `APP_HOST` | `127.0.0.1` | Интерфейс локального Uvicorn |
| `APP_PORT` | `8000` | Локальный API / опубликованный порт Compose |
| `VITE_PORT` | `5173` | Порт frontend в разработке |
| `SESSION_DAYS` | `30` | Срок сессии в днях, 1–90 |
| `COOKIE_SECURE` | `false` | Принудительный Secure для cookie за HTTPS-прокси; при прямом HTTPS включается автоматически |
| `AUTH_ALLOWED_ORIGINS` | `[]` | Дополнительные доверенные Origin в виде JSON-массива, например `["https://words.example"]` |

Compose задаёт собственный `DATABASE_URL=sqlite:////data/word_guess.db`, внутри контейнера сервер слушает порт 8000. Windows-БД по умолчанию — `data/runtime/word_guess.db`. Все соединения включают WAL, `foreign_keys` и `busy_timeout`; данные должны находиться на локальном диске.

Изменяющие `/api` запросы требуют заголовок `X-Requested-With: word_guess`. Переданный браузером Origin должен совпадать с адресом сервиса либо явно указанным доверенным адресом. Vite сохраняет исходный Host при проксировании. Все ответы API имеют `Cache-Control: no-store`. Регистрация и вход ограничены десятью запросами на логин и тридцатью на IP за пять минут; ограничитель рассчитан на один процесс сервера и очищается при перезапуске. Регистрация атомарно создаёт аккаунт, настройки, сессию и стартовый бонус.

API аккаунта: `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`; оформление — `GET/PATCH /api/settings`. Схема `0002_accounts` добавляет таблицы `users`, `sessions`, `user_settings`, сохраняя существующий словарь.

Партии: `GET /api/games?mode=4|5|6` возвращает последнюю партию выбранной длины либо `null`; `POST /api/games` начинает или возвращает активную, `GET /api/games/{id}` восстанавливает её. Попытка — `POST /api/games/{id}/guesses`, сдача — `POST /api/games/{id}/surrender`. Запуск требует UUID `operation_id`, изменение — тот же ключ и текущую `version`; при повторе сохраняйте исходные поля. Миграция `0003_games` добавляет партии, строки и журнал ключей. Изменения сериализуются через `BEGIN IMMEDIATE`; частичный уникальный индекс допускает одну активную игру на пользователя/длину. Пароли, цена, ответ и результат не принимаются от клиента.

Экономика: `GET /api/inventory` возвращает монеты, предметы и очки по длинам; `GET /api/shop` — каталог; `POST /api/shop/purchases` принимает `item` и UUID `operation_id`. Применение — `POST /api/games/{id}/hints` с ключом, версией, `kind` и `position` только для целевой подсказки (нумерация API с нуля). Виды: `random_letter`, `position_letter`, `eliminate`. Ключи попыток, сдачи и подсказок общие внутри партии; при изменении полей нужен новый ключ. Ответ партии содержит актуальные `economy`, `hints` и сохранённую `reward`.

Миграция `0004_economy` добавляет кошельки, денежный журнал, инвентарь, награды и использованные подсказки. Bootstrap выдаёт прежним аккаунтам стартовый бонус и начисляет награды за сохранённые завершённые победы, каждый результат ровно один раз; активные партии сохраняются. Повторный или конкурентный bootstrap не дублирует начисления. Баланс и остатки защищены проверками SQLite, условными UPDATE и журналом уникальных ключей. Не запускайте старую версию сервера одновременно с обновлённой схемой; обновляйте через обычные сценарии запуска после остановки сервера.

Повторить проверку, миграции и импорт вручную:

```powershell
.\.venv\Scripts\python.exe -m backend.app.bootstrap
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini current
```

Схема изменяется через `backend/migrations`, `create_all` при запуске не используется. Импорт атомарный, сохраняет идентификаторы слов и не создаёт дубликаты при повторах или одновременных импортерах. Ошибка миграции/контента/импорта останавливает старт. Health возвращает 503 до готовности миграций и словаря, затем 200; ответы не кэшируются.

Автоматизация backup/restore относится к этапу 9. Для работающей SQLite резервное копирование должно использовать SQLite backup API с учётом WAL; готовый сценарий ещё не добавлен.

## Подготовка и проверка контента

Проверено в Windows PowerShell на Python 3.13.9. Нужен Python с pip и venv; Node.js для этих инструментов не требуется. Зависимости устанавливаются только в `.venv`, версии и SHA256 закреплены в файле требований.

Из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r scripts/content-requirements.txt
.\.venv\Scripts\python.exe scripts/fetch_content.py
.\.venv\Scripts\python.exe scripts/prepare_words.py
.\.venv\Scripts\python.exe scripts/verify_content.py --require-target
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_content.py -v
```

Первые установка и загрузка требуют интернета. `fetch_content.py` сохраняет оригинальный пакет в игнорируемом Git каталоге `data/sources`, проверяет SHA256 и не перезаписывает существующий файл с неверной суммой. Полный текст лицензии хранится в репозитории. `prepare_words.py` читает локально установленный словарь, применяет решения из `reviews.json` и заново формирует CSV и JSON-отчёт. Полный проход словаря может занять несколько минут.

Проверка уже подготовленных данных без сети и без морфологических зависимостей:

```powershell
python scripts/verify_content.py --require-target
```

Проверка воспроизводимости по установленному снимку без перезаписи файлов:

```powershell
.\.venv\Scripts\python.exe scripts/prepare_words.py --check
.\.venv\Scripts\python.exe scripts/fetch_content.py --check
```

Воспроизводимость толкований и дополнительных вводов (после установки dev-зависимостей):

```powershell
.\.venv\Scripts\python.exe scripts/prepare_definitions.py --check
.\.venv\Scripts\python.exe scripts/prepare_guesses.py --check
.\.venv\Scripts\python.exe scripts/prepare_words.py --check
```

Первая команда требует исходный gzip-снимок в `data/sources`; для загрузки и подготовки используйте `scripts/prepare_definitions.py --fetch`. URL Kaikki обновляется: если его SHA256 изменился, загрузка останавливается, нужен зафиксированный снимок, а не молчаливое обновление источника. Для пересборки данных последовательно выполните `prepare_definitions.py`, `prepare_guesses.py`, `prepare_words.py` без `--check`, затем `verify_content.py --require-target` и bootstrap. Обычный запуск использует уже сохранённые CSV/JSON и не загружает словари из сети.

`--require-target` завершает проверку с ошибкой, если хотя бы одна длина содержит менее 1000 одобренных ответов. Проверка без этого флага проверяет целостность, но допускает исследование дефицита.

Основной сайт OpenCorpora при проверке 27.10.2026 возвращал HTTP 403/522. Использован снимок 0.92/revision 417150 из пакета `pymorphy3-dicts-ru 2.4.417150.4580142`, скомпилированный 08.01.2022. Это не текущая XML-выгрузка. Происхождение, контрольные суммы и изменения зафиксированы в [sources.json](data/words/sources.json) и [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Производные словарные данные распространяются по CC BY-SA 3.0.

Открыть `http://127.0.0.1:8766` и нажать воспроизведение. Трек повторяется через стандартный браузерный `loop`; доступны громкость и пауза, автозапуска нет. Остановка сервера — Ctrl+C; другой порт: `--port 8767`. Сервер доступен только с этого компьютера и отдаёт только страницу предпросмотра и трек.

Прослушивание по указанию пользователя перенесено на этап 8. Бесшовность музыкального стыка не подтверждена: браузерный повтор сам по себе её не гарантирует. Проигрыватель игры, сохранение настроек и пауза при скрытии приложения будут реализованы на этапе звука.

## Будущее приложение

Итоговое приложение предусматривает четыре режима: 4/5/6 букв и кампанию, сундуки каждые десять уровней, рейтинг и PWA. Сейчас доступны первые три режима, аккаунты, темы, очки/монеты и магазин подсказок. Игра без энергии, рекламы и платежей. Ответы, правила и экономика находятся на сервере.

Используется React 19.3.1 + TypeScript 7.0.2 + Vite 8.3.5, React Router 7.18.5, TanStack Query 5.105.0, FastAPI 0.162.0, SQLite + SQLAlchemy 2.0.55 + Alembic 1.20.1, argon2-cffi 25.1.0. Зависимости закреплены в lock-файлах. Следующий функциональный этап — кампания, затем сундуки и рейтинг.

Способы запуска:

| Окружение | Команда |
| --- | --- |
| Docker Compose | `docker compose up --build` |
| Windows без Docker | `.\run.bat` |
| Разработка в Windows | `.\run-dev.bat` |

Миграции и импорт уже работают. Автоматизация backup/restore и установка PWA ещё не реализованы.
